# Add a "comment WHY, not WHAT" code-comment rule to fkit, and remove the rules that contradict it

**Source**: `ai-agents/tasks/done/0506-add-a-why-not-what-code-comment-rule-and-remove-the-rules-that-contradict-it/brief.md`
**Status**: done — `✅ Done (agent-closed — not owner-verified)`
**Sprint/Tag**: Sprint 10 `P20` (append rank) · task `0506` · owner `fkit-coder`

## Goal
Owner request 2026-10-10 (R10, ⚠️ the lead's relay): brief a task from the owner's own report
`report-3-code-comments.md` (copied beside the brief as `source-report.md`). **The problem:** code Claude Code writes is
heavily commented — sometimes 5–10 comment lines around 1–2 lines of code. Three costs: **stale comments** (the biggest
risk — an agent treats a comment as true, so an outdated one gives confident, wrong information), **token cost** (every
read pulls comments into context; compaction comes sooner), and **noise** (the one real warning gets buried).

**The fkit-shaped job:** put the rule where every fkit agent reads it, for every fkit user, and remove what pushes the
other way — notably `fkit-coder.md`'s *"match its naming, structure, comment density, and idioms"*, which in a
heavily-commented file told the coder to keep commenting heavily.

⚠️ **The tension the brief left to the owner:** fkit's own tree is commented heavily **by design** (ADR pointers,
owner-ruling citations, review finding IDs, the reasons behind guards). **Owner ruling 2026-10-10, option (c):**
*"Code yes, prompt texts no (Rec)"* — the rule applies to fkit's code (`claude/*.sh`, `bin/`, `test/`); skill and agent
prose (`SKILL.md`, `claude/agents/*.md`) is not held to it.

## Key Changes
- **Plan rulings (2026-10-14, `AskUserQuestion`):** a **hard rule**, with *"a project's own comment rules win"*; scope
  **(i)** — only new and edited code follows the rule, the existing-code cleanup is separate work; fkit only — the
  owner's personal `~/.claude/CLAUDE.md` was checked read-only and holds nothing about comments, so nothing to remove.
  Plan approval: *"Approve, cuts C1–C6 (Rec)"*; optional cut C7 **not signed, not applied**.
- **New convention `code-comments.md`, dual-homed and byte-identical** (live + scaffold) — the full rule: (1) comment
  only WHY, never WHAT; (2) at most 1–2 lines, a longer reason goes to the knowledge base with a one-line pointer **by
  name or ID, never by line number** ([[tasks/write-the-durable-citation-anchors-convention-page]]); (3) no history
  comments; (4) no name-repeating comments; (5) keep non-obvious decisions, platform/SDK/harness gotchas, workarounds and
  must-not-break reasons; (6) fix or delete a comment your change makes wrong, in the same edit; (7) doc comments on
  public functions one short line unless genuinely complex. **Scope:** code (source, scripts, tests, config), **not**
  prose documents; new and edited code, not a wholesale rewrite. **Precedence:** a project's own written comment rules
  win; *"match the surrounding code"* means naming, structure and idioms — **never comment density**. **Enforced in
  prose only** — nothing checks it automatically.
- **Rules block** (`claude/scaffold/universal-rules.md`): a new last hard-rule bullet — *"**Code comments say WHY, never
  WHAT**; fix or delete one your change makes wrong. A project's own comment rules win. Full rule:

  none dropping a rule: C1 *"…win, …win, …win"* → *"all win"*; C2 the wiki rule loses *"; writes are not"*; C3 *"Say it in

  "What's next?"**…"*. Root `CLAUDE.md` / `AGENTS.md` regenerated by init, no hand edit.
