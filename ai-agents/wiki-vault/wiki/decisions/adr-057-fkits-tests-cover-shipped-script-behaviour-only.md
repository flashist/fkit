# ADR-057: fkit's tests cover shipped-script behaviour only — the test-scope reset (option D)

**Date**: 2026-10-19
**Status**: accepted *(owner sign-off 2026-10-19, Q7, `AskUserQuestion`, `fkit lead` session; append-only since — five dated append passes by 2026-10-20, one of them a ⛔ on §D1 and one a ⛔ on §D7; no decision withdrawn)*

**Replaces**: the fence of [[decisions/adr-014-how-fkit-tests-itself]] §2 (D1). **Retires**: the enforcing tests of the reference-integrity condition (D6) and the undocumented "fourth category" (D7). **Stands beside, not over**: [[decisions/adr-026-no-mutation-testing-library-prove-red-stays-hand-rolled]] Decision 4 (the ADR's own *"amends"* wording was corrected by a dated note: Decision 4 stands, only its lane and case count drift), [[decisions/adr-017-skills-may-ship-executables-invoked-via-bash-not-the-exec-bit]] rule 4 (taken in unchanged), [[decisions/adr-027-dual-home-parity-is-a-dev-time-convention-plus-test]] Decision 2 and [[decisions/adr-029-a-task-is-a-folder-keyed-by-a-permanent-global-id]] Decision 3 (their tests stay, now licensed by D7).

> ⭐ **Ingested 2026-10-23** (sync `96c7263`→`5ccf2c2`) from `ai-agents/knowledge-base/decisions/adr-057-fkits-tests-cover-shipped-script-behaviour-only.md`, read whole with its dated notes. Built by task `0527`; carried out by `0528`–`0530` — see [[tasks/the-test-scope-reset-tasks-0526-0530]].

## Context
**The owner's decision, typed 2026-10-19** in a `fkit lead` session: *"I am making a decision that we need to RADICALLY reduce the tests in fkit: I belive we're in the "self-enforced-loop" when tests and further development creates more tests and more re-runs of the same tests. … We no longer are ok with such insane amount of time needed for tests."*

**The evidence the ADR cites** (consult figures from `0527`'s brief, not re-measured by the ADR):
- **Growth 2026-07-15 → 10-17:** test files 1 → 42; prove-red mutations 2 → 55; test lines ~250 → ~22.3k plus prove-red's 2,533 — against ~7.3k lines of shipped shell/JS. CI median job W33 244 s → W42 778 s (max 1320 s).
- **The loop:** of 35 tasks closed since 2026-09-16, 19 touched tests, 11 added a test file, 5 added mutations, 4 were about the test system itself. *"No rule ever retires a test."*
- **Where the time went** (slowest CI run, 1310 s): seven whole-suite passes 48% (the unit pass plus prove-red's `run_suite` ×6); the update-banner group 32%.
- **How the fence grew:** ADR-014 §2 (*"exactly two things … it stays this size"*) → ADR-017 rule 4 (a third) → a "fourth category" (repo-content invariants) recorded **only in test-file headers**, never in an ADR. A dated note corrects the ADR's count of files claiming it: **14**, not 5.
- **Task `0526`'s answer** fed D8: mutation 48's ~217 s is a test-harness cost, not a launcher bug.

The owner's rulings: (1) *"the option that is reducing the time most radically"* — the lead's reading, option D, **confirmed by the owner** 2026-10-19; (2) *"≤ 2 min, CI-enforced"*; (3) owner-approved growth only; (4) check mutation 48 first (`0526`). Q1–Q6 then settled the open points; Q7 signed it off.

## Decision
- **D1 — the fence.** A test may cover **only the behaviour of a shipped script, seen from outside**: **category 1** — the launcher, init, the hooks, and `claude/skills-for-role.sh`; **category 2** — shipped skill executables (`dashboard.sh`, `throughput.mjs`, heal `check.sh` / `repair.sh`). Not: **3** repo-only `bin/` tooling, **4** the wording or shape of shipped prompts and documents, **5** this repo's own `ai-agents/` content — except D7's named list. LLM behaviour stays out.
  - ⛔ **Dated note 2026-10-20 (owner ruling A3, Sprint 14):** the board module `board/` is **inside** the fence — its tests under `test/board/` count *"because the board will ship"*, run **inside the default `npm test`** (task `0417` added `test/board/*.test.js` to the script) and **inside the 2-minute budget**. Not a fifth D7 exception.
  - ⚠️ **Dated note 2026-10-20 ([[decisions/adr-058-the-read-only-board-reader-ships-to-every-fkit-user-as-fkit-board-ahead-of-the-merge]]):** `bin/fkit-board.mjs` now ships, so it is a shipped script inside D1 — but **no test file for it is pre-approved**.
- **D2 — growth stop.** (1) No new test file and no new prove-red case without the **owner's OK**, each one, in any lane. (2) **No numeric cap** — the owner's Q3 answer (*"we just need to be sure our tastings don't become bloated and enormous"*) replaced ruling 3's *"under a cap"*. (3) A missing test on correct code is a **suggestion, not a defect** — except the **key list** (Q2): the launcher's argv incl. whether it `exec`s; the role-lock `skillOverrides` matrix; the skill-ownership hook's allow/deny; any code path that writes or deletes a user's file (init convergence / never-overwrite, orphan cleanup, heal `repair.sh`).
  - ⚠️ **Dated note 2026-10-20 (A3):** the owner's OK given **in advance** for **at most 6** test files under `test/board/`, one each for `0417`–`0422`. `0423`'s Python-vs-Node check is a one-off script, not a kept test.
- **D3 — prove-red.** Out of the default `npm test`, into a **nightly CI lane**, cut to **four cases** — M1 (skills_for_role entry → only `test/skill-ownership-hook.test.js`), M2 (`--resume` passthrough), M30 (cold-start `exec`), M31 (intake-path `exec`) — the last three run only `test/launcher-contract.test.js`. The other 51 are deleted. The owner (Q1) accepted that a failure is seen *"the next morning … that's fine for now"*. Not chosen: delete it entirely; run it by hand only.
  - Dated notes record the build: `0529` kept the numbers M1/M2/M30/M31 (owner ruling) and left a window with **no automated gate**; `0530` added `.github/workflows/prove-red.yml` (`cron: '17 3 * * *'`, plus `workflow_dispatch`), which takes effect only once on `main`. The cost note adds ~39–68 s of green baselines to the ~97 s the owner was told — arithmetic, not measured.
- **D4 — the reviewer's must-keep list.** The four category-1 items stay by D1. The release tool's test **leaves the default suite** for its own script (Q4a); scaffold-vs-dogfood byte parity **stays** in it (Q4b). Dated notes: the test moved to `test/release/release-summary.test.js` (`npm run test:release`), and `bin/release.mjs` now runs **both** `npm test` and `npm run test:release` before its first write (`0530`, owner *"Release test too"*).
- **D5 — ADR-029 D3's duplicate-ID check stays** (Q5), as a named exception — **fkit's own repo only**; consuming projects get none. Upgrade path, if wanted: a shipped check in `dashboard.sh`.
- **D6 — the reference-integrity condition.** Its two enforcing tests go. (a) The four movers stop telling the producer to run `test/reference-integrity.test.js`; the producer's own resolve-every-link hand check becomes **the** check, and the close report says no automated link check ran (backlog `0522` superseded). (b) The *"a link is a pointer, a `path`+line cite is a claim"* principle survives as a **written rule with no test**.
- **D7 — the fourth category is retired.** Named exceptions only: `test/dual-home-parity.test.js`, `test/task-id-uniqueness.test.js` (default suite), the release tool's test (own script) — ⛔ **plus a fourth, by owner ruling R1 2026-10-19:** `test/structure-manifest.test.js`, the only check that the shipped manifest matches its generator.
- **D8 — banner tests:** their fate is `0526`'s finding. Rule for new tests only: *a new timing test must not sleep for real.*
- **D9 — prompts that must change** are listed by file and quoted phrase. Shipped prompts get **project-neutral** wording (Q6): *follow the project's own test rules and key list; a missing test on correct code is a suggestion unless the project's key list names it; run the project's default test command.* fkit's own rules live in `CONTRIBUTING.md` and the knowledge base.
- **D10 — the budget:** default `npm test` ≤ 2 min locally on an idle Mac; CI fails the job if it goes over. Non-default lanes are outside it.
- **D11 — other ADRs that name a test:** their decisions stand; only the enforcing test may go. Drift notes were written when `0529` actually deleted each test (12 ADRs, per the 2026-10-20 note).

## Consequences
- **Positive:** default `npm test` targets ≤ 2 min instead of ~12 min locally / ~13 min median in CI; the suite stops growing by default; upkeep and false reds from content and wording tests go.
- **Costs accepted with the sign-off:** *"risk of silent role-lock bugs"* — reduced, not removed, by the four nightly cases and the key list; a broken role-lock test found **next morning**; the link / citation guards, ADR-number uniqueness in the suite, prompt-frontmatter and wording guards, and 51 of 55 prove-red cases go; consuming projects with no written test rules get "missing test = suggestion" everywhere.
- **Re-raise only if:** a role-lock or `--resume` regression ships; the nightly lane fails unnoticed (then run it on every push); the budget is breached and the fix proposed is "raise the budget"; the suite grows back **inside** the budget (then a numeric cap); a duplicate ID costs real work in a consuming project; a deleted guard's failure class recurs twice. **Do not re-raise** "add a test for X" on correct code outside the key list as a defect.
- **Measured outcome** (from `0529`/`0530` worklogs, not the ADR): 19 test files deleted, 22 kept in `npm test`, 1 moved; prove-red 2,533 → 305 lines; local `npm test` 845/845 in ~77–89 s **under load, not idle-Mac figures**; CI budget step 60.7–85.2 s on the runner (slowest 71% of the 120 s budget).
