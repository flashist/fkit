## Accepted residuals (shared, do-not-re-litigate)

- **Installer owns `$SHARE`, links included (R4)** — What: `install.sh` treats `$SHARE` as wholly fkit's own and follows links under it, so a hand-made symlinked `$SHARE/bin` or `$SHARE/vendor` (or an `FKIT_SHARE` folder that already holds its own `vendor/aiboard/`) gets `bin/fkit-board.mjs` / `vendor/aiboard/` removed and re-copied through that link. Why (structural): guarding only `bin/` and `vendor/` would still leave `claude/` unguarded (the existing `rm -rf "$SHARE/claude"`), and refusing or skipping on a link changes install behaviour for that setup; anyone who can write `$SHARE` already controls the launcher. Owner ruling, 2026-10-20, fkit-lead session, typed reply verbatim: "Accept as a known cost". Re-raise only if: a fresh install or update itself creates a link under `$SHARE`, or a user reports a real loss.
