## Accepted residuals (shared, do-not-re-litigate)
- **R2 — path safety is lexical (symlinks not followed)** — What: `carry-check-hook.mjs` path safety rejects absolute paths, `..` and empty segments, and a `resolve()`d path outside `cwd`; it does not `realpath`, so a symlinked directory under `cwd` pointing outside lets the hook read and hash a file outside `cwd` and, on mismatch, echo its blob id in the deny reason. · Why (structural): the hook's threat model is a mistaken driver, not a hostile one (`0162` §10 row 3); the read is read-only and the prompt already carries the file's bytes; the only exposure is a 40-hex blob id of a file the session could read anyway. Rejected: `realpathSync` + re-check — adds a second filesystem round-trip and a new failure mode (a dangling symlink now reads as "unsafe" instead of "dangling") for no change in what a driver can be caught doing; a `git ls-files` membership check — spawns git, which the plan chose not to do. Owner ruling 2026-08-26 ("Fix R3+R7, residuals for R2/R5/R6"). · Re-raise only if: the hook's threat model changes to a hostile prompt author, or a deny reason is ever routed anywhere other than the session's own stderr/model.
- **R5 — "exact bytes" is a UTF-8 text compare** — What: the paste check is `prompt.includes(bytes.toString('utf8'))`: the file's bytes decoded as UTF-8 (invalid sequences → U+FFFD) must appear verbatim in the prompt string. For valid UTF-8 — the only thing a JSON prompt can carry — that is byte-exact; the hash leg always checks the true bytes. A `plan.md` that is not valid UTF-8 cannot be carried verbatim through a JSON prompt at all and will be denied by the paste check. · Why (structural): the prompt arrives as a JSON string, i.e. already text; a byte compare would need the prompt re-encoded, which is the same comparison. Headers keep the phrase "exact bytes" with this entry as its gloss; rewording every site buys nothing. Owner ruling 2026-08-26. · Re-raise only if: a plan.md is ever legitimately non-UTF-8, or the hook payload stops being JSON.
- **R6 — `process.stdout.write` + `process.exit` on a deny** — What: the deny JSON is written with `process.stdout.write` then `process.exit(0)`. On macOS a pipe is asynchronous in node; a write larger than the pipe buffer can be cut at exit (verified 2026-08-26: 200 000 bytes → 65 536 arrive; `fs.writeSync(1, …)` delivers all). An unparseable deny is ignored by the harness (= allow). Reaching it needs a `permissionDecisionReason` of ≥64 KiB, i.e. a pointer path or hash of that length in the prompt — theoretical for a mistaken driver. · Why (structural): the cheap hardening (`writeSync`) is one line, but it is a change on the deny route that ADR-018 D3's tests pin and prove-red exercises; the owner chose to record it rather than touch the route this round. Owner ruling 2026-08-26. · Re-raise only if: a deny reason ever includes prompt text of unbounded length (today it includes only the path, the two hashes, or fixed prose), or the harness stops ignoring malformed hook JSON.
- **R1 / R13 — a partial line with anything glued after the cut counts as driver text** — What: "file content" for the degraded-form scan is an exact file line or a ≥ `PREFIX_MIN` (12) char PREFIX of one. A partial file line with anything glued on after the cut on the same line — the tail of a later file line (a mid-paste elision), an inline `[... N chars truncated ...]` marker, or driver text such as an END fence not on its own line — is neither, so it is scanned as driver text and its `pointer-only` / `by reference only` words declare the degraded form; a paste cut that way is allowed when the hash matches (reproduced 2026-08-26 for all three shapes). The tool-cap TAIL cut (the shape the hook exists for) is covered because the ship loop's END fence sits on its own line. · Why (structural): the hook sees lines, not positions; telling a glued line from a driver line needs either a paste-region marker in the rule text (the rule-text edit Q2 ruled out) or substring-level matching of every prompt line against every file line (quadratic, and it would swallow genuine driver lines that happen to contain a file fragment → false denies). Rejected on both counts. Owner ruling 2026-08-26 ("Record as residual", with R13's widened wording). · Re-raise only if: a real spawn is found allowed on a glued line, or the ship loop's fenced form changes so the fence is no longer on its own line.
- **R7 / R9 / R14 — the line-set narrowing cannot tell WHOSE a pointer line is** — What: pass 1b drops pointer X as content when X's line is a line of another pointer Y's readable, hash-matching file. That covers two shapes beyond the intended one (a plan quoting another task's pointer): (1) a DRIVER-text pointer line byte-identical to a line of a pasted plan is content and is not gated; (2) the TARGET's own pointer is un-gated when a sibling plan on disk quotes the target's current pointer line and is pasted in the same spawn — a truncated target is then allowed (reproduced 2026-08-26; pinned as documented behaviour by the R7 and R9 tests). A pointer line that differs by one byte is gated. The mutual-quote pair (two pointers vouching for each other, incl. a self-quoting plan found by a ~2^28 nonce search) stays gated — the guard is pinned (R12). **And (3, R14) the near-miss WARNING is likewise silent for a driver line byte-identical to, or a ≥12-char prefix of, a content line of any readable pointer file** — the R11 exclusion uses the same position-blind line set, so a driver that copies a mis-formed pointer line out of the carried plan gets no stderr courtesy (before R11 it warned, count 2); the decision is unchanged either way (Q1), and a line one byte different still warns (reproduced 2026-08-26; pinned by the R14 test). · Why (structural): the hook has no notion of where a line sits or which file a paste belongs to; the narrowing was owner-ruled ("narrow via the D1 line set") to stop faithful carries of quoting plans from failing closed, and the R11 exclusion (owner "Keep", 2026-08-26) to stop every faithful Build of a form-quoting plan from false-alarming. Rejected: counting occurrences (treat X as content only when the prompt holds X's line no more times than the pasted copies of Y account for) — it flips the pinned "byte-identical line outside the paste → allow" case to deny and adds a second position-blind heuristic on top of the first; the owner chose "Residual, widened wording + pinned test" over it, and the same heuristic on the warning channel (R14 option c) falls with it. Reachability of (2) is low: the sibling must quote the target's LIVE hash and be pasted in the same spawn. Reachability of (3) is low and its cost is warning-only. · Re-raise only if: a real Build spawn is found un-gated by shape (2), the rule text gains a machine-readable paste-region marker that lets the hook place lines, or the WARNING is ever routed to the model or made blocking (then (3) stops being a courtesy).
