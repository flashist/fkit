## Context

**Nothing runs fkit's test suite before a release, and the release script does not run it either.**
Verified on disk 2026-08-08:

- **No CI at all** — `.github/` does not exist (`ls .github` → no such directory). The suite runs
  only when a human remembers.
- **`bin/release.mjs` runs no tests.** Its sequence is bump `VERSION` + `package.json` → `git add -A`
  → commit → push → tag → push tag. There is no test invocation anywhere in it.
- **The suite is real and is the thing not being run** — `npm test` is
  `node --test test/*.test.js && bash test/prove-red.sh`, with **19** `test/*.test.js` on disk
  (2026-08-08) plus the hand-rolled mutation gate.

**The concrete failure this permits.** `claude/structure-manifest.tsv` is a *shipped artifact*
regenerated by `npm run generate:manifest` whenever `claude/scaffold/` content changes;
`test/structure-manifest.test.js` asserts byte-equality against a fresh regeneration and prints
`"→ fix: npm run generate:manifest"` when stale. That guard is the only thing standing between a
scaffold edit and a **shipped, wrong hash table** — and today it fires only if someone ran `npm test`
by hand. `git add -A` in the release script will happily commit and tag the stale manifest.

**This discharges a standing open question, and the owner has now answered it.**
[`architecture.md`](../../../knowledge-base/architecture.md) §11 open question 2 — *"Is the test
suite going to CI? … Is a `.github/workflows/` that runs `npm test` (plus `shellcheck` + a smoke
install for `install.sh`) in scope, or is run-it-yourself the accepted posture for a prototype?"* —
closes with **"An owner call, not an architect's."** The owner made that call on **2026-08-08**,
relayed through the coordinating session: **fix it, don't just record it.**

⚠️ **The ruling is "build a gate", not "build the §11 wording".** §11's question names a *broader*
scope (shellcheck, an `install.sh` smoke install) than the defect above requires. Do not treat §11's
parenthetical as the approved scope — see "What to build" §1.

**Related, already-recorded facts, so the plan does not re-derive them:**
[ADR-014](../../../knowledge-base/decisions/adr-014-how-fkit-tests-itself.md) established how fkit
tests itself and states *"no CI, no test suite, no `.github/`"* as its **starting** condition;
[ADR-003](../../../knowledge-base/decisions/adr-003-ci-runs-validate-bundles.md)'s CI **never
landed** and its subject (`omnigent/validate-bundles.sh`) died with the Omnigent removal — so there
is no live CI decision to be consistent with, and no rejected alternative to reopen.
[ADR-026](../../../knowledge-base/decisions/adr-026-no-mutation-testing-library-prove-red-stays-hand-rolled.md)
keeps `prove-red.sh` hand-rolled — whatever gate lands must run it, not replace it.

## What to build

**Weigh the options first; do not assume the answer.** The owner ruled *that* a gate exists, not
*which*. The plan must pick one and justify it against the others.

1. **Weigh at least these three, with the tradeoff stated for each:**
   - **A `.github/workflows/` that runs `npm test` on push/PR.** Catches everything, including work
     that never goes near `bin/release.mjs`, and is the answer §11 anticipated. Costs: a new
     surface with no prior art in this repo, and it does **not** by itself stop a release cut from a
     dirty laptop — CI green ≠ the tree being tagged is green.
   - **A test gate inside `bin/release.mjs`** — run `npm test` before the bump/commit, abort
     non-zero. Directly closes the stated defect at the exact moment it matters, needs no new
     infrastructure, and is zero-dependency (ADR-014). Costs: it gates **only** releases, so §11
     OQ2's *"nothing runs it automatically"* stays **substantially true**; and it slows every
     release by the suite's runtime, `prove-red.sh` included.
   - **Both** — CI for continuous signal, the in-release gate for the artifact actually shipped.
2. **Whichever is chosen, these properties are required, not optional:**
   - It runs the **full** `npm test`, i.e. the contract suites **and** `prove-red.sh` (ADR-026).
   - **A failure blocks the release** — it must not warn-and-continue. A gate that can be ignored by
     not reading stdout is not a gate.
   - **Measure and record the suite's wall-clock runtime** in the worklog. If an in-release gate is
     chosen, that number is the cost the owner is accepting; state it rather than implying it.
   - If an escape hatch is added (e.g. `--no-test`), it must be **explicit, loud in the output, and
     documented** — never a silent default.
3. **Update `architecture.md` §11 open question 2** to record the ruling and what landed, following
   the pattern OQ1 already sets (kept as a closed pointer, not deleted). **If the chosen option is
   the in-release gate alone, say so plainly — OQ2 is then only partly discharged**, and §9.1's "No
   CI" bullet remains true and must not be softened.

### ⛔ Out of scope

- ⛔ **`shellcheck` and an `install.sh` smoke-install job.** §11's parenthetical names them; the
  owner's ruling did not. Both are real gaps (§9.1 records `install.sh`'s zero coverage) and both
  are their own briefs. **Do not fold them in** — an `install.sh` e2e needs a clean `$HOME` and is a
  materially different piece of work.
- ⛔ Any change to a test file, to `bin/generate-structure-manifest.mjs`, or to
  `claude/structure-manifest.tsv`. This task runs the suite; it does not edit it.
- ⛔ Any new npm dependency (ADR-014, zero devDependencies).
- ⛔ Replacing or restructuring `prove-red.sh` (ADR-026).
- ⛔ Rewriting `architecture.md` §9.1's suite inventory — that is
  [`0251`](../../backlog/0251-refresh-architecture-md-section-9-test-suite-inventory/brief.md). If both are
  open, coordinate; they touch different sentences in the same section.
- ⛔ Any `ai-agents/wiki-vault/` write (ADR-005).
- ⛔ No commit, no re-rank, no task-file move.

## Verification steps

1. **The gate demonstrably blocks.** Introduce a deliberate failure — edit a `claude/scaffold/` file
   **without** regenerating the manifest, so `test/structure-manifest.test.js` goes red — then run
   the release path (`node bin/release.mjs --dry-run`, and/or the CI job) and show it **refuses**.
   Revert the deliberate break afterwards and prove it is reverted (`git status --porcelain` clean
   of it).
2. `npm test` is green on the final tree.
3. The chosen option is justified in the plan against the other two, with the rejected ones' reasons
   recorded — not merely listed.
4. The suite's measured wall-clock runtime is in the worklog as a number.
5. `architecture.md` §11 OQ2 records the ruling and its date, and — if only the in-release gate
   landed — says explicitly that OQ2 is partly discharged. `grep -n "No CI" ai-agents/knowledge-base/architecture.md`
   still returns §9.1's bullet unless CI actually landed.
6. `git status --porcelain` shows nothing under `ai-agents/wiki-vault/` and no change to any
   `test/*.js` file.
