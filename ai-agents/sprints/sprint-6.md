### ✅ The one convention deviation — declared rather than made silently, and now RESOLVED

**Status: ✅ RESOLVED 2026-08-14**, in the same act that recorded the ranks above. The record is **kept,
not deleted** — this reasoning is why `backlog.md`'s rule changed.

**The rule it deviated from.** [`backlog.md`](backlog.md)'s **"How work moves on and off this board"**
states the forward move as **three mandatory edits**, and said of the marker
`➡️ Moved to [Sprint N](sprint-N.md) — priority M` that *"the `— priority M` component is **not**
optional here"* — **unconditionally**.

**The deviation, while it stood.** The 18 backlog rows carried the marker **WITHOUT** that suffix. The
reason: `M` is defined by that same passage as *"the priority the task gets in Sprint N"*, and on an
unranked board **there is none**. Writing `— priority —`, or a number, would either be noise or the
exact act ADR-035 forbids. The same file's **reverse** move already stated the governing principle for
an unranked destination in so many words — *"**No `— priority M` suffix**: this board is unranked, so
there is no destination rank to name"* — and that reasoning transferred to an unranked **forward**
destination unchanged. ⚠️ **The rule as written was not merely awkward, it was unsatisfiable**: no
unranked destination could comply with it at all.

**✅ How it was resolved — both halves, 2026-08-14, each on an owner ruling of the same session:**

1. **The rows.** This board is now ranked, so the destination rank **exists** and the suffix is owed.
   Each of the 18 rows on `backlog.md` gained its **`— priority P<n>`** suffix, matching the ranks in
   the table below. ⛔ **Task and Brief cells were left byte-identical** — the Status cell is the only
   thing that changed, and `backlog.md`'s own Priority column still reads `—` throughout, which stays
   correct: **that** board is unranked by design.
2. **The rule.** `backlog.md`'s **"Off:"** rule gained an **unranked-forward clause** making the suffix
   conditional on the destination board being ranked — mirroring the reverse move's existing wording
   rather than inventing a new shape, and stating that the omission is a **deferral**: when the board is
   later ranked, every moved row's suffix is added in that act. **Owner ruling, the option label is the
   verbatim text: "Add an unranked-forward clause (Recommended)".**

⚠️ **Checked, not assumed — and re-checked after the change:** `dashboard.sh`'s `moved_target` parser
matches `Moved to \[*(<sprint-id>|Backlog)` and lets `.*` swallow everything after the identity, so it
**never reads the suffix**. Adding the 18 suffixes therefore changed **no count, no drift verdict and no
`next` value** — `backlog.md` still reads `count backlog 89`, `count moved 40`. This was a
**documentation-truth fix, not a behaviour change**, in both directions.
